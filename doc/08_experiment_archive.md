# 实验记录归档（问题定位与结果汇总）

本文件合并原 `03~07` 的实验记录，只保留仍然重要的实验问题、证据和结论；已经明确修复或不再影响当前判断的实施细节不再重复。完整数值明细仍可从 `doc/results_summary.csv` 与 `doc/planning_results.csv` 追溯。

## 1. 当前已经确认的主问题

- BaseLine carrier 正常：零残差关闭时，输出与 BaseLine 完全一致，说明主 carrier 路径没有坏。
- 退化集中在 DSQE 残差侧，尤其是动态 / motion 相关路径。
- `feature residual` 当前不是主要矛盾：单独开启时与 zero residual 几乎一致。
- 角色监督没有学稳，`dynamic_f1` 接近 0，`gt_dynamic_ratio` 极小，`mean_role_on_moving_gt` 长期低于 `mean_role_on_static_gt`。
- `query_motion` 基本失活，训练日志里其均值和 P95 长期为 0。
- 动态 residual 幅度偏大，存在过度修正而非稳定细化的迹象。
- Oracle 条件无法恢复指标，说明问题不只是 pose 或 role 的单点错误，而是未来点 / 语义联合演化链路本身有问题。

### 2.2 轨迹恒等性检查

对 zero residual 与 BaseLine 的规划输出做逐样本比较，64 个样本的轨迹差异为：

```text
trajectory max_abs_diff: 0.0
trajectory mean_abs_diff: 0.0
PASS: zero-residual trajectory matches BaseLine
```

这条检查把问题范围缩得很窄：carrier 主路径正常，真正引入退化的是 DSQE 残差侧。

### 2.3 当前判断

- `point-only` 不是单独“修好”或“修坏”整个系统，而是说明点残差在未来预测里确实会影响结果，且对长时域动态更不稳定。
- `semantic-only` 能在较长 horizon 上带来部分回升，但仍无法把整体指标拉回 BaseLine。
- `feature-only` 与 zero residual 相同，说明 feature residual 不是当前主问题。
- 综上，问题不是某一个残差头单独出错，而是动态 / motion 相关的联合残差链路不稳定。

## 6. 归档结论

当前所有实验合在一起，问题可以收敛成四条：

1. carrier 主路径没坏，问题不在 BaseLine 主干；
2. DSQE 动态 / motion 路径不稳定，是主要退化来源；
3. 角色监督和 `query_motion` 都没有真正立起来；
4. oracle 条件和阶段 1 结果都说明：未来点 / 语义联合演化链路需要继续定位，而不是继续只看单个指标。
